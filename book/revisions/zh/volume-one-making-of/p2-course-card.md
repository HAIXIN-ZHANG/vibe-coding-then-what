# 标题长了半行，按钮去哪儿了？

设计稿里的课叫“摄影”。两字配一张山景，下面留着足够的空白，看着挺想报名。老师发来的全名是“带着旧手机去海边：阴天也能拍的周末摄影入门”，没有配图。你把这门课放回同一张卡片，才发现原来那份从容，有一大半是“摄影”这两个字替你挣来的。

假设这还是我们的课程列表。第一版搜索只给卡片两样东西：课程编号和标题。小林想先认出课程，再沿编号去看哪天上课。列表能给他的是一个“查看课程”的入口，几点开课要等详情读到场次才知道。图片有时能帮人选课，比如认出要学的构图；这位老师恰好没有图，读者仍该能靠文字选。先把山景拿走，看还能不能认出课程、打开详情，比替他临时找一张海鸥照片省事。

## 宽度花到哪里去了

假设窄屏上这张卡分到了 320 个 CSS 像素，两边各留 16 个像素，里面还剩 288。横排一张宽 96 的图，再留 16 的间距，留给文字和入口的就只有 176。你给卡片写上“宽度百分之百”，消失的那一百多像素也不会回来。盒子里的内容、内边距和边框各自占多少，要连同用的是哪种盒模型一起看。

在宽屏上，把多张卡放进网格往往很方便。每一列有自己的轨道，课程标题可以在列里换行。卡片内部若用 Flex 排图和文字，能不能缩小还受子项的最小尺寸约束。一串很长的课程代码，中间连一个可断的位置都没有，很可能把文字列撑出卡片。允许文字区收窄，例如给那个 flex 子项设 `min-width: 0`，是给盒子让路；让长代码有可接受的断行位置，是给内容让路。只做前一件，盒子缩进来了，字还可能伸在外头。

可以依次放进三张卡。第一张题目很长，但文字本身能换行；第二张塞进一串连着的课程代码；第三张干脆没有图。如果三张都固定为两行的总高度，第一张的查看入口很容易被挤掉，第二张让你看见断行的限制，第三张则可能留下一个空空的相框。这些问题分开出现，比较容易知道刚改的那行样式究竟帮了谁。

## 小林到底认的是哪一个名字

把刚才那门课复制一张，只改名字的尾巴。第一张叫“周末摄影入门：海边实拍”，第二张叫“周末摄影入门：室内静物”。后台编号各不相同，详情页也确实各归各家。把浏览器放窄，若两张都成了“周末摄影入门……”，搜索这一步从程序看来完全正常。小林要找海边的课，只好多打开一页。可惜他来此的目的，也不是替我们测试浏览器的后退按钮。

你可以给每一张卡一个固定高度，先保住整列对齐。两张课名都短的时候效果很好；遇到这两个长名字，可以让课名换行、卡片按需要长高，下面那排便要一起往下挪。如果页面用绝对位置把入口钉在第二行下方，新增加的第三行就会压到按钮。单独给长标题缩字号也容易让最难分清的一行恰好最小。把两个名字丢进同一排，打开到刚好要换行的宽度，然后只把字放大一级。名字读全了吗？第二张入口还在自己的标题后面吗？这样检查的时候，不用先猜小林拿着哪一款手机。

图片又提出了另一个问题。原型有一个“图片可空”的字段，第一版真实的搜索回应里却压根没有图片字段。可以约定缺图就走纯文字卡；也可以在详情加载以后再显示老师选的照片。若光为保住那张卡的比例，就给每门课都配同一张山景，它至少得安安静静做装饰。让读屏工具替每张卡念一遍“山景图片”，听到第七座山的时候，报名页还在山的另一头。

同样是两张纯文字卡，页面要交给键盘使用者的线索也有区别。假设各有一个链接，光看字都叫“查看课程”。拿掉周围的标题，只听这两个入口，很难决定按哪一个。可以把课程名本身做成链接，也可以让入口的可访问名称带上对应的课名，页面上仍用简短的“查看课程”。若整张卡已经能导航，又在里面嵌了一个做同一件事的链接，小林可能得按两次 Tab 才能经过同一门课。实际走一次，从列表开头到第二门课，记录每一次焦点到了什么地方，往往比数设计稿里画了几个边框更有用。

顺便看一眼输入和结果之间的距离。小林看到“室内静物”，发现自己搜错了，想把搜索词改回“海边”。宽屏桌面上搜索框和两张卡都在视野里，窄屏上第二张也许落在下一屏。若卡片等图片加载后才突然长高，刚准备点的链接在指尖底下跑走了。预留确有尺寸的图片区，或干脆从开头就用纯文字布局，可以避免这一次位移。它和标题太长的问题看起来都像“按钮去哪儿了”，修起来却在找两样东西。

## 少放一列以后

空间缩到图、字、入口要争位置时，可以把图放在上面，让标题按内容长高，“查看课程”接在后面。也可以在这一级列表省去装饰图，让人先比较课程名称。哪种好，要看图片有没有帮人分辨课程。若两门课的区别就在两张不同的画作上，删图之前，倒该先想想还有什么办法把这点区别交给读者。

有些设计喜欢把入口钉在卡片底部，让一排卡的按钮对齐。这很好看，前提是长标题也有地方安放。允许整排随内容增高，代价是短卡多些空白。把标题截成一行则节省了高度，可两门都从“周末摄影入门”开头的课，也许要读到最后三个字才能分开。亲手找一次“进阶班”，你很快就会知道省下的是谁的空间。

用键盘沿列表往下走，也值得看一遍。屏幕上第一张卡的标题和入口挨在一起，文档里的顺序最好也让人能这样读下去。仅用视觉排序把第三张挪到最前，焦点还照原顺序走，读者的眼睛就得跟按钮玩捉迷藏。窄屏换行、放大文字、拿掉图片以后，读者仍该能看出焦点落在哪个入口上。卡片移入时轻轻抬起，本来只是装饰，即使关掉动效，选中状态和入口照样应该清楚。

把那门真的很长的摄影课放在第一张，再试一次。要是课程名读得完，“查看课程”也找得到，这张卡就已经比设计稿多回答了一个问题。入口总算找得到了。校方又有一个愿望：能不能少点一下，干脆在卡片上就让人报名？
