# “确认报名”要换颜色，为什么课程链接也跟着变了？

第二所学校愿意用这个课程网站了。对方发来一份校徽，顺便提了个小要求：“确认报名的按钮，能用我们这个紫色吗？”

假设你接手时，两页已经照上一节约好了。列表里，学员可以点“查看课程”，先看看几点上课。到了详情页，点“确认报名”才会提交。这次连按钮上的字都不用改。你找到样式表里那行蓝色，把它换成校徽的紫色，再开详情页。白字，紫底，挺精神。

回到课程列表，“查看课程”那几个字也紫了。旁边有个标着“已选”的筛选项，连它的边框都跟着换了校服。

## 顺着这个蓝色往回找

这几处为什么会一起变？把这家虚构网站的样式缩小一点，就容易看见。假设两所学校各有自己的课程区，下面这段只管浅色页面。三个位置原来都从课程区取同一份蓝色：

```css
.school { --blue-700: #17468c; }
.enrol { background-color: var(--blue-700); }
.course-link { color: var(--blue-700); }
.filter-selected { border-color: var(--blue-700); }
```

这是 CSS 自定义属性的一种用法。`--blue-700` 给一个具体色值起了名字，`var(...)` 让用色的地方按名字取值。按钮取它来填背景，链接取它来写字，筛选项取它来画边框。如果你在第二所学校的课程区把这个名字对应的值改成紫色，里面这三处就都会拿到紫色。对着按钮检查一遍，你甚至会觉得改得很准确。

这里值得问的，是这三处当初为什么一样蓝。第一所学校喜欢用蓝色来突出页面上最主要的动作。“查看课程”带着下划线，沿用的是站内文字链接的颜色。筛选项的蓝边框配着“已选”两个字，帮人找回自己刚才选的条件。调色板上的答案碰巧相同，负责这些地方的人却各有理由。第二所学校想认领其中一个理由。那位提要求的同事，大概没打算重新设计筛选器。

## 给用途也留一个名字

可以先把蓝色留在原处，紫色作为另一个可取的值。然后给按钮、链接和选中边框各留一句交代，它们是为哪件事来取色的。两所学校套用同样的规则，第二所只另写有差异的那一行：

```css
.school {
  --blue-700: #17468c;
  --purple-700: #60328f;
  --action-fill: var(--blue-700);
  --link-text: var(--blue-700);
  --selected-border: var(--blue-700);
}

.school.second { --action-fill: var(--purple-700); }

.enrol, .save-profile {
  background-color: var(--action-fill);
  color: white;
}
.course-link { color: var(--link-text); text-decoration: underline; }
.filter-selected { border: 2px solid var(--selected-border); }
```

这段替换前一段。第二所学校的外层元素同时有 `school` 和 `second` 两个类，按钮、链接和筛选项都在它里面。拿手指从“确认报名”往回走，先找到主要动作的底色 `--action-fill`，再找到紫色。换到链接，手指走的是另一条路，经过 `--link-text` 又回到原来的蓝色。筛选项也有自己的去处。下次有人想改文字链接，可以从 `--link-text` 查起，不用对着所有蓝色猜一遍。

设计里常把这种有名字、可以引用的设计值叫作 *design token*。蓝和紫是供人挑选的基础色值，`700` 在这里只是这套色阶里的编号。到了“主要动作底色”这一层，名字说的是用途，常叫语义 token。一个主题可以给这个用途选蓝，另一个选紫。组件照着用途取值，两所学校就能继续共用同一个报名按钮。

## 让同一张卡在两校各待一晚

颜色约定最容易在交接那天失效。设计师把学校乙的样张发过来，同事从截图里吸出紫色，直接填进“确认报名”的背景。这一张卡第二天还是对的。换到同一页的资料表单，那里也藏着一个主操作。它该不该跟着紫？再换回学校甲，假如两校老师恰好在两扇窗口里同时预览，刚才那次替换影响的是哪一扇？

不要急着搜整个项目里有几个同样的十六进制数。先把学校甲的页面复制一份，内容保持完全一样，只换最外层的学校标识。第一眼可以看按钮，再往下读课程链接，最后看两个输入框之间的边界。若按钮紫了，带下划线的链接和边框保留各自原来的作用，我们才有机会一项一项问校方。若连边框都跟着紫，改动大概落在三处共同依赖的原始色值上。这个小实验每次只改变主题作用域，才能看出是谁牵动了谁。

再用灰度的想象试一次。链接如果同时有下划线，颜色变浅仍能认出它可以跟过去。按钮有可读的动作名称和清楚的焦点样式，换肤不会要求学员先知道学校乙喜欢什么颜色。可输入框出错若只靠边框从蓝变紫，校方原以为是在换一套校色，学员可能以为自己已经填错一整张表。要在错误旁边留下可以读到的原因，主题只能替它换外观。

## 还有一个按钮也变紫了

细看上面的样式，有一行还带着 `.save-profile`。假设学员修改自己的邮箱，页面下方有个“保存资料”。这里也把保存当作页面的主要动作。照现在的写法，第二所学校的“保存资料”是什么颜色？

也是紫色。至于这回算不算改错，得把两个按钮摆给提需求的人看。如果学校想让主要动作都跟校徽走，这就是改对了，两处只要认同一个名字。假如对方看过才说：“保存还是留着蓝色吧，我们只想在报名时用校色。”那就让主要动作底色继续用蓝，给报名按钮单独留一个“报名底色”。平时它引用主要动作底色，第二所学校才单独把报名底色指向紫色。“保存资料”仍取原来的值。这一层多出来，是因为现在真有两件事要分开改。要是往后始终一起变，维护者每查一次颜色，就平白多走一步。

假设学校看过两张图，回信说：“这次只换报名，保存资料照旧。”把这句回复留在改动说明里。验收时，先开第二所学校的报名页，看白字紫底的“确认报名”，再去改邮箱。如果“保存资料”也是紫的，校徽的颜色用得再准，这份改动也该退回来。上一段代码还共用主要动作底色，正好会被这一步查出来。要是回信说“这两个都换”，同一个紫色保存按钮才算过关。第一所学校在两种约定下都照旧，报名和保存都是白字蓝底。

按这封“只换报名”的回信改，先删去前面那行第二所学校对 `--action-fill` 的覆盖，其余样式照旧，再加三行：

```css
.school { --enrol-fill: var(--action-fill); }
.school.second { --enrol-fill: var(--purple-700); }
.enrol { background-color: var(--enrol-fill); }
```

现在再去改邮箱，“保存资料”取到的仍是蓝色。还有两处容易被漂亮的报名页挡在视线外。回到两边的白底课程列表，链接都该是带下划线的蓝字，选中的筛选项都保留蓝边和“已选”文字。假设页面另有一个“取消报名”，它沿用独立的警示配色，也写清楚会取消什么。学员扫一眼文字，就知道该不该把手指移开。

颜色要放回它旁边的颜色一起看。报名按钮的白字在那块紫底上看得清吗？链接挨着正文，还有下划线可认吗？即使把两个按钮的背景值都核对过，这两件事仍值得亲眼看一遍。这里看的只是浅色页面上列出的几种状态；换深色底、移入指针或用键盘把焦点移过来，眼前又是另外一组要看的东西。

所以下次再遇到两块一模一样的蓝色，可以先把颜色选择器放一放。想象一下第二所学校来的那天，问一句：“如果只改左边这一块，右边也应该跟着变吗？”答案要是“还真得问问”，那你已经找到了该拿哪两个界面去问。
