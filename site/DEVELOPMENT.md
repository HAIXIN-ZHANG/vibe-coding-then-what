## Environment and commands

Use Node.js 24 LTS and npm 11; `.nvmrc` selects the Node major. Dependencies are pinned in `package.json` and `package-lock.json`. Run from the repository root:

```sh
npm ci
npm run dev
```

Next normally reports `http://localhost:3000/`; follow the actual reported port if occupied. There is no database or background application service.

```sh
npm run check
NEXT_PUBLIC_BASE_PATH='' npm run build
NEXT_PUBLIC_BASE_PATH='' npm run verify:export
```

`prepare` runs Panda codegen after installation. `dev`, `build` and `typecheck` also run codegen explicitly, so ignored `site/styled-system/` output is reproducible. `check` runs ESLint, typecheck and the Node regression suite covering routing/deployment, theme, reviewed content and search/sharing. `typecheck` generates Next route declarations, then runs the application and isolated Panda build-tool compilers. A clean checkout needs no earlier build. Static output goes to ignored `site/out/`.

Project links are configured in `site/config/site.ts`; book titles and interface messages are in `site/config/i18n.ts`. No chapter prose is copied into React components. The renderer implements the narrow [initial content contract](../docs/content-contract.md); adding further manuscripts requires their own review and allowlist authorization.

## Source-to-page reader

`site/content/manifest.ts` contains three explicitly approved entries (opening, G01 and F01), each with ID, locale, slug, source title, order, source path, SHA-256, reviewed-draft status and review reference. The manifest requires unique identity/route/source and increasing order. `load-book.ts` reads only those files at build time, resolves filesystem paths inside `book/`, verifies source bytes before parsing, and verifies the first H1 against the reviewed title. Hash mismatch, absent file, escaping symlink, unsupported Markdown or invalid link fails the build. It never crawls the book/planning tree. These three chapters are in the recorded public release above; the earlier two-source edition is historical. Run commands from the repository root, as above.

The pinned parser is `mdast-util-from-markdown` 2.1.0 with `micromark-extension-gfm-table` 2.1.2 and `mdast-util-gfm-table` 2.0.1; `@types/mdast` 4.0.4 is a direct development type dependency. Only table extensions are enabled. Usage follows the maintainers' [CommonMark AST parser](https://github.com/syntax-tree/mdast-util-from-markdown) and [table extension](https://github.com/syntax-tree/mdast-util-gfm-table) documentation, checked 2026-11-16. There is no MDX, raw-HTML pass-through, HTML-string injection or runtime Markdown fetch. Typed AST nodes render as React text/semantic elements; raw HTML and unsupported nodes fail explicitly. Reference-style links/images/other extensions are not currently supported by this renderer and require a separate reviewed addition.

Parsing preserves headings, paragraphs, inline emphasis/code, lists, citations, tables and exact fenced-text values. The source H1 renders once. Only the exact `> 中文初稿 · 待 review` preamble immediately after that H1 is omitted; substantive or later blockquotes survive. Deterministic NFC/Unicode heading IDs use collision-safe suffixes; the outline derives from actual H2–H4 nodes. Relative links resolve only to allowlisted sources and real target heading IDs, then become canonical chapter routes. Native heading links expose stable anchors. Unsafe schemes, control characters, protocol-relative links and unapproved relative destinations are rejected.

`book.ts` deduplicates validation/parsing within a React server-rendering pass. Server-only composition receives the AST. Client interaction boundaries receive composed navigation, individual code strings, locale or public chapter/heading/source-hash metadata as needed; the canonical AST is not passed to client components. Search fetches its public static index on demand. Chapter route parameters derive from the same loaded manifest allowlist, with dynamic parameters disabled. ## Local Continue

The chapter directory can show one **Continue reading** panel above the available chapters after hydration. First visits, unavailable storage, malformed/unsupported records and removed chapters show the ordinary directory. The panel displays current source-derived chapter and optional section titles; English UI marks the destination and its Chinese titles as a Chinese original. Its native link is deliberate: chapter visits and shared fragments never redirect to saved progress. The server-rendered directory, manuscripts and existing no-JavaScript links remain usable without the panel. The homepage has no Continue entry.

`reading-locator.ts` projects only allowlisted chapter IDs, titles, routes, reviewed source hashes and live heading IDs/labels from the parsed sources. It excludes manuscript bodies, source/review paths and legacy aliases. `vctw.reading.v1.last` stores one strict, bounded record containing version1, chapter ID, nullable heading ID and source hash; stored data never supplies a route or title. A changed source hash or missing heading resolves to the current chapter start with a short notice. A removed chapter or invalid record produces no link. Resolved native links apply the deployment prefix once and encode only a validated live heading ID.

The mounted chapter recorder observes trusted document-moving wheel/touch/scroll-key intent in the prose or reading navigation, and deliberate real same-chapter section-link activation. It records the current live heading, not pixels or completion percentages, at most once per750ms. Passive entry, shared-fragment landing, focus changes, restoration and layout movement do not save a position. Compositor scrolling can precede wheel delivery, so the recorder compares against the last observed document offset. Header/dialog controls and local element scrolling that does not move the document do not count as reading activity. Tracking never moves focus or scroll.

Storage property access, reads, writes and read-back verification are guarded. A failed write disables that mounted recorder instead of repeatedly retrying or creating a volatile saved-success value. Pending work is discarded on hidden/pagehide/unmount, another tab changing/clearing the reading key, or an opening dialog/popover; writes are also suspended while hidden or overlaid. Only matching localStorage events affect progress; theme/accent keys and sessionStorage events remain separate. A new deliberate activity can resume capture after an overlay or another tab's update. The feature adds no account, synchronization, bookmarks, analytics or network requests. Browser storage can be cleared or denied and is not a backup or cross-device guarantee.

## Static search and section actions

`site/content/build-search-index.ts` extracts plain text only from the already validated canonical chapter trees. Each real heading starts an entry with chapter/heading IDs and titles, locale, reviewed source SHA-256, canonical unprefixed heading URL and its following text. The generated resources are `/search-index/zh.json` (entries derived from the approved chapter headings, currently 28 in the local intake) and `/search-index/en.json` (empty). They are force-static GET outputs, not request-time APIs or extra manuscripts. Source paths, review files and internal directory scans never enter the index. The export verifier compares both JSON files with fresh canonical extraction and verifies every target against actual HTML IDs.

`site/content/search.ts` performs literal NFKC/case/whitespace-normalized substring matching. Whitespace-separated terms all need to occur in heading/chapter/body text; Chinese does not require word segmentation. Heading matches rank above incidental body mentions; exact heading matches rank first and ties retain manifest order. All matching sections are returned and accessible; the status reports that actual total. There is no regex query execution, fuzzy/stemming/semantic search, backend or added dependency. Excerpts select a window of normally 64 original graphemes around a body match, extending it when needed to retain that match, with explicit ellipses for omitted context. Normalized offsets map back to original grapheme boundaries, preserving compatibility expansions, combining sequences and supplementary characters. Matching text uses semantic mark elements without injecting HTML; short excerpts are generated around a hit rather than hiding it with CSS clipping. This remains a small-corpus literal matcher, not a general search engine.

A normalized exact chapter-title query groups only inherited-title-only section hits into one chapter result per locale/chapter identity. Genuine heading/body matches retain every original fragment, including H1. The transient result kind/href does not modify the index schema/entries. Chapter results sort first and show an explicit Chapter/Section label; the current full browser title produces2 destinations (chapter route plus real H1) while `报名` remains14. Non-exact query ranking/excerpts/Unicode behavior and current-language boundaries retain their earlier semantics. See the [exact-title handoff](../docs/handoffs/developer/m2-exact-title-search.md) for actual checks/limits.

Header Search opens a native modal dialog with a real labeled input and close control. It fetches the current-language resource only on Chinese search opening, keeps the fetched index in the mounted control, and retains query through close/reopen or failure/retry. English deliberately presents absent-corpus guidance and a Chinese-index link without fetching Chinese results. Loading lasts for the actual request; HTTP/JSON/schema errors expose retry while retaining the query. Native modal background inertness, arrows between input/results, Enter activation, Escape/outside close and prior-focus restoration are implemented; shortcut hints disappear below 900px. Cmd/Ctrl+K ignores editable fields/composition. Chromium may report BODY when Tab moves to browser controls; that is distinct from background page controls receiving focus. The implementation retains native behavior without a custom JavaScript trap; checks verify background controls cannot receive focus and keyboard navigation resumes inside the dialog. Simulated IME checks are separate from physical keyboard/input-method verification.

Escape is handled explicitly after the composition guard because populated native search inputs may otherwise consume it to clear text. Cancellation restores the opener/shortcut's previous focus. Result activation clears that restoration callback. Section results retain native anchors, so default fragment navigation assigns focus to the actual destination heading after immediate dialog close; the next Tab stays in the article. These literal result anchors and JSON fetch URLs prepend the build prefix once; ordinary Next Link paths remain unprefixed. Cross-chapter section navigation deliberately uses the static document. Grouped chapter results use a real unfragmented Next Link: on the current chapter, history changes to the actual chapter URL and focuses its real H1; across chapters, a temporary observer transfers focus only when the exact destination URL (including hash/query) and real chapter H1 commit, then disconnects. User input, a competing URL/history change, page exit/unmount or a10s abandoned-navigation deadline cancels its ownership; this cleanup deadline never retries navigation or delays a successful result. It adds no fake fragment/storage and does not restore focus to the closed search control.

`SectionActions` is a small details disclosure after each source heading. The original native heading anchor remains available; no repeated default card is added. Copy builds the actual origin/path/encoded-heading URL on interaction, preserving any Pages prefix once and removing unrelated query data. Clipboard failure/absence reveals a selectable read-only URL; success uses a live announcement without requesting focus or scrolling. Correction first previews chapter/heading/source revision/actual URL locally, then offers an editable GitHub issue-draft link. Nothing is submitted automatically; no private logs, manuscript file paths or model request is attached. Runtime origin-dependent values are produced only in event handlers, avoiding hydration-time URL guesses.

Search/action styles use existing semantic roles, shared Button states and explicit Panda token expressions. UI04 feedback/input/card geometry is reused; mobile layouts adapt to the actual content and real buttons rather than copying Figma's spaced header text or simultaneously showing specimen states. Root/Pages export verification preserves all earlier assertions and adds JSON/heading-action checks; the search/sharing handoff retains its original state/focus/clipboard/screenshot evidence. Maintained E2E now checks representative reading/recovery flows as described below; it does not replace every earlier browser or design review.
